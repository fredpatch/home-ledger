# P1.5 — Operations API (plan) · APPROVED 2026-10-08 · phase-1 · after P1.3, P1.4

**Goal**: server API for operations (create / edit / soft delete / list + filters) and settings. No client, no migration.

## Rules (source)

- **R2** (spec §R2; decisions 2026-10-07): class and envelope come from the category, never from the request (a `class` field → 422). Field matrix = `validateOperationShape`. Unknown/inactive category or account, unknown project/loan → 422.
- **R3** (spec §R3): `budgetMonth = budgetMonthFor(date, category.rollsOver, settings.budget_rollover_day)` unless the request sends `budgetMonth` (manual override). On edit (Q9): recomputed when date or category changes, unless the stored value differs from the value computed for the old row (= manual override, kept); `budgetMonth: null` clears the override.
- **R7**: a project purchase, or a transfer linked to a project, must leave a `fundsProjects` account (BGFI épargne).
- **R10** (decisions 2026-10-07): a loan operation creates its `loans` row in the same transaction; a repayment needs an open loan and sets it `settled` when repayments reach its amount; above the remaining balance → 422 `exceeds_remaining` (Q6).
- **Data model** (spec §Modèle de données): amount = positive safe integer XAF; dates 'YYYY-MM-DD'; soft delete via `deleted_at`. Every edit/delete → `change_log` before/after JSON in the same transaction; creates are not logged.
- **Validate before write**: the full check runs in the service; `computeTheoreticalBalance` trusts its input (TASKS note). DB CHECKs and triggers stay the last line of defence.
- **Pot** (decisions 2026-10-08; Q3, Q4): pot = sum of live "Chargement du pot" operations in the budget month. Pot-funded budgets > pot + `pot_budget_tolerance` → `warnings[]` in the 2xx response of writes touching that category, never an error.
- **Settings** (decisions P1.4): allowlist only, `auth_*` never read or returned. Bounds: `budget_rollover_day` int 1–28, `cash_tolerance` and `pot_budget_tolerance` (new, seeded 0) int ≥ 0, `savings_target_percent` int 0–100; `opening_date` read-only (Q10). Settings edits not journaled (Q5, Phase 2).
- **Security** (PROJECT §Security): routes mounted after `requireSession` + `requireCsrf`; no amounts in logs or error bodies.

## API

`GET /api/operations?month&from&to&accountId&categoryId&class&limit&offset` (non-deleted, date desc) · `GET|PATCH|DELETE /api/operations/:id` (a second DELETE → 404; PATCH and DELETE need `expectedUpdatedAt`, mismatch → 409 `conflict`, Q7) · `POST /api/operations` · `GET|PATCH /api/settings`. Errors: 422 `validation_failed {issues:[{field,code}]}` · 404 `not_found` · 409 `conflict`.

## Tests

- **Unit**: request parsing (`class` rejected; amount 0/-1/1.5/text; bad dates; manual `budgetMonth`) · R3 on days 24/25 with the configured rollover day · pot check below/at/above tolerance · settings bounds.
- **Integration**: 401 without a session and 403 without CSRF on every mutation · each class created + R2 rejections · R3 rollover · R7 wrong source → 422 · loan creates its receivable, a repayment settles it (Q6) · edit/delete write `change_log`, a rejected write leaves no row · deleted operations hidden from the list · list filters · settings: `auth_*` never returned, unknown key → 422, bounds · pot warning present/absent · no amounts in logs.
- **Fix loops**: `npm test` + the affected compiled integration file only, `node --test <file>` (ask tier, Q8).
